## 2. 用户已确认的核心玩法

1. 只有与车颜色相同、**当时与道路相邻**的球可被该车接走。这里的“路边”是道路邻接判定，球团其他外轮廓不自动算可接；也不能隔着球接内部球。车辆须行经相应接球路段。每次只接当时符合条件的一批；新露出的球要等后续合法接球事件。
2. 车上显示的 `100`、`200`、`104` 等数值是容量。未满载的车沿轨道持续循环，后续仍可接同色球；满载后自动驶离，**立即释放一个道路车位**。`0/6` 表示道路上已有车辆数／道路车位上限。
3. 只有车库中未被其他车挡住、能够驶出的车可以派出。道路未满时，即使当前路上车辆暂时接不到球，仍允许继续派车。
4. 常规死局条件：场上还有球，道路已占满 6 个车位，且路上车辆即使继续循环、等待球稳定后也无法接走任何球。不能因车还没走到接球点、落球仍在进行、或道路未满而过早判负。自定义 Demo 可配置车位数时，使用该关上限替代 6。
5. 全部球清空才满足用户提出的过关核心要求。当前 Demo 还要求所有待发车和道路车辆清空，这是实现层面的更严格条件；修改过关定义时须显式处理多余车辆。
6. 接球会留下空位，其余球会移动、下落；球可以跨列斜落。接球顺序、球色暴露和车库挡车共同构成解题过程。

### 已确认的普通落球优先级

用户后来明确规定了下列顺序，取代早期“只按列竖直下落”的猜测：

1. 正下方为空且移动路径畅通：向下移动。
2. 正下方受阻，只有左下可进入：向左下移动。
3. 正下方受阻，只有右下可进入：向右下移动。
4. 正下方受阻，左右下都可进入：**优先向右下**移动。
5. 三个方向都无法进入：停止，等待局面变化。

等价判定顺序是：下 → 右下 → 左下。合法移动必须在球区内，目标格空闲、路径不穿过其他球或边界；移动后更新占用，重复至稳定。为保证同样的关卡与操作得到同样结果，需要固定同一轮内的遍历和冲突顺序。视觉动画应呈现直落与斜落；加速只改变模拟时间速度。当前 Demo 对“路径畅通”还采用同侧格空闲的具体判定，详见其 `README.md` 和 `src/gravity.js`。

### 道具与其他 Demo 约定

用户选择 Demo 包含三种免费、无限次数的道具：清除（移除指定待发车）、打乱（重排待发车）、磁铁（移除指定道路车并释放车位）。用户明确选择了 **B**：清除和磁铁只删除车，既不删除球，也不补车或补运力；这样可能造成运力不足，可通过重开或编辑关卡恢复。打乱不改车辆颜色和容量。Demo 同时提供暂停、重开、加速。

## 4. 梯形球区：目标与待确认的补位提案

用户给出的新目标：球区为**上宽下窄的梯形**；底层球离开后，只要剩余球数多于底层宽度，等待局面稳定后底层应始终铺满。实际数学条件可放宽为“剩余球数不少于底层合法格数”。这个目标是已明确的需求，但下面的实现方法**尚未由用户确认，也不能当作已在 Demo 实现**。

单用上述“下 → 右下 → 左下”局部移动，可能出现底层有空格而球堆稳定在另一侧，因此不能保证目标。此前提出的补位方案是：

1. 先执行普通落球直到稳定。
2. 若底排有空位且剩余球数不少于底排宽度，从一个底排空位开始，在合法格中沿“上、左、右”搜索通往上层现存球的路径；搜索可以穿过已占用的底排格。
3. 沿找到的路径把球依次移入前一个空位，即底排球可横移，上方球沿路径补入底排；保留球的身份和颜色，不生成、删除或瞬移球。
4. 重复修复底排空位，再继续普通落球，直到稳定且底排铺满。固定空位处理、搜索邻居和路径选择顺序以保证结果可复现。

此方案**额外允许同一行横向挪球**，会改变颜色的暴露顺序；必须在用户接受后才应用到游戏逻辑、编辑器、回放与生成验证。保证成立所依赖的条件是：球区每行合法格连续、越往上不比下一行窄、内部没有隔断、球可按上述路径横向移动。若有内部障碍或分区，单靠总球数不足以保证底排满。之前用宽度依次为 7／5／3 的小梯形穷举了全部 32,647 个“球数不少于底排宽度”的占用状态，提案均可补满底排；这只是小模型验证，不等于现有引擎已通过测试。

**当前实施边界**：Demo 的现有说明描述的是矩形球区与普通直落／斜落规则。若后续要做梯形，应先确定几何掩码、同排横移是否接受、以及补位期间的表现和接球时序，再统一修改引擎、编辑器、生成器、验证器与回放。

## 5. 核心循环、关卡设计与难度

核心循环：观察当前路边球色与车库可派车辆 → 选择发车顺序、管理有限道路车位 → 车辆经过接球路段，容量递减 → 球区下落并改变可接球色、车库队列前移 → 满载车辆离场腾出车位 → 重复直到清空或死局。玩家的主要抉择是**先派谁、何时占位、哪辆车能解开下一层球、哪辆车挡着关键车辆**。

手工关卡设计方法：

1. 先定该关要教或考的一个主要问题，再设计一条不使用道具的可复现通关路线。
2. 依据真实接球与落球模拟布置颜色层和车库挡车关系。让玩家能从当前可见信息推断下一步，避免只能盲猜。
3. 校验各色球数与对应车辆总容量；若要求所有车最终满载离场，应逐色相等。总量相等只是必要的数量检查，不证明可解。
4. 在解法周围加入有意义的岔路，核验失误是否可察觉、是否会占满道路，且关卡仍存在无道具解。
5. 用实际引擎回放派车顺序与落球过程，记录最高道路占位、关键车解锁点、等待次数和死局原因；规则变化后重新验证。

三关原定教学节奏：第 1 关认识同色接球与满载离场；第 2 关理解分阶段暴露和车库挡车；第 3 关考道路车位规划，包含真实错误分支和无道具正确路线。难度应来自依赖链和可逆选择的变化，不能只增加球数。

随机关卡算法的设计方向：模板化构造一条可解路线 → 根据目标颜色数、球区尺寸、容量与车位做有界扰动 → 检查结构与逐色运力 → 用**与游戏一致**的确定性模拟器寻找通关路径 → 按指标筛选并保存种子、配置、解法和统计。求解器必须纳入当前球格、落球、道路车辆及位置／剩余容量、车库阻挡关系；只算颜色总数会误判。找到路线即已证实可解；预算内没找到只能标“尚未证实”，不能标“无解”。

可用于评价难度的指标包括最优解所需最高道路占位、可安全选择的派车分支比例、关键车辆被挡的深度、要预见的球色暴露层数和错误决定到失败的延迟。仅有一条通关路线给出最高占位的**上界**，不能据此称最优难度；随机策略成功率也不是人类通过率。最终难度仍须靠试玩数据校准。对外发布更适合从已验证的离线关卡池抽取。
