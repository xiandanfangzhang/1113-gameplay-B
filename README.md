# 彩球接驳 Demo

一个无需后端、无需 npm 依赖的中文浏览器解谜游戏。三个内置关卡默认采用**宽 60、高 20 的矩形球区**；编辑器可按关卡自由设置宽 1–100、高 1–60。有可视化关卡编辑器、随机关卡与随机车辆生成，以及无道具快速通关验证。

## 启动与构建

需要 Node.js 20 或更新版本。在项目目录执行：

```powershell
node scripts/dev-server.mjs
```

打开 <http://127.0.0.1:4173/>。构建并检查静态发布目录：

```powershell
node scripts/build.mjs
node scripts/dev-server.mjs --dist
```

构建结果在 `dist/`，可以部署到任何静态文件托管服务；现有 `.openai/hosting.json` 也指向该目录。浏览器须支持 ES Modules、Canvas、Pointer Events 和 `structuredClone`。

运行规则测试与三个关卡的真实逻辑回放：

```powershell
node --test
node scripts/replay-levels.mjs
```

回放结果见 `replay-report.json`，人工解法见 [SOLUTIONS.md](./SOLUTIONS.md)。如需重新写入回放报告，执行 `node scripts/replay-levels.mjs --write`。

## 如何游玩

1. 在顶部选关。点击车库每列最前面的车辆派车；同列后车要等前车离开车库。
2. 车在道路循环。经过球区底边的对应路段时，只接走正上方、与车同色的球；扩大的车辆面板逐车显示剩余容量。
3. 满载车自动离场并释放车位。全部球、待发车和路上车清空才通关。
4. 操作台可重开、暂停、切换 1×/2×/4× 速度。清除先选道具再点任意待发车；磁铁先选道具再点路上车；打乱立即重排待发车。道具免费且不限次数，按“取消道具选择”退出选择状态。
5. 画布可拖动平移、缩放；点小地图可快速定位。手机触屏同样可操作。

道具只移动或删除指定车辆，不删球、不补车、不改容量。道具造成运力不足时会显示按颜色计算的缺口，仍可随时重开。

## 如何编辑

### 按图案生成球区

在编辑器“图案球区排布”区点击“打开球区图案生成工具”，或直接打开 `/pattern-tool.html`。上传图片，或选择“字符图案”并逐行输入 `R` 红、`B` 蓝、`Y` 黄、`G` 绿、`O` 橙、`P` 紫、`.` 空格；设置宽 1–100、高 1–60，点击“生成排布”预览并下载 JSON。字符图案的行数和每行格数必须与宽高一致，可用空格或逗号分隔字符。图片按比例居中适配，透明及接近白色的像素为空格，其余像素映射为最接近的六种球色。

回到编辑器点击“导入球区排布”选择该文件。导入只替换宽、高和小球，保留关卡名称、车库、道路车位上限；无效文件不会改变草稿。若已有未保存修改，导入前会确认。导入后检查逐色运力差异和车辆容量；球数匹配不代表可通关。此排布文件格式为 `{ "format": "color-transit-ball-layout", "version": 1, "width": 60, "height": 20, "balls": [...] }`，与整关导入使用的 version 5 JSON 分开。

顶部进入“关卡编辑器”并选关。在“关卡属性”中输入球区宽度和高度，点击“应用球区尺寸”。调整时保留左上角重叠区域的小球，新增格为空；缩小会先确认裁掉的球数。颜色画笔和橡皮可连续鼠标拖动或触摸涂画；“矩形填充”适合一次修改较大球团。“拖动画布”、缩放及“全图/底部”帮助定位球格。道路随底边宽度调整，车库仍为三列。全图单格较小时可放大涂画。

在“随机关卡生成”里勾选 **1–6 种颜色**，点击“生成到当前关卡”即可按当前宽高生成球区和车辆。随机种子留空时每次点击会生成新布局，并显示本次种子；也可填写 0–4294967295 的整数以复现同一布局。每种颜色配一辆车，容量等于该色球数；选用四种或更多颜色时，同列会有后车，须先派出前车。生成会覆盖当前编辑草稿，未保存修改会先确认；生成结果不会自动保存，可继续编辑、即时试玩、保存到本机或导出 JSON。

生成器按连续 5 个合法格子分组，并随机排列色组。各色球数和对应单车容量都是 5 的倍数；若球格总数不是 5 的倍数，末尾 1–4 格留空。球格不足以给每色至少分配 5 球时会报错。默认 6 个道路车位时，全部所选车辆均可上路，每辆车继续循环接走其颜色的球；不同种子仍应使用快速验证或试玩检查。关卡自定义道路车位上限会保留。

“随机车辆”只替换当前草稿的车库，**不修改球区**。输入 1–3 列、每列 1–12 行后，生成器会填满指定矩形的合法车位，给每种现有球色至少一辆车，并让每色车辆总容量与该色球数精确相等。**每辆随机车辆的容量至少为 5 且是 5 的倍数**；因此每种颜色的球数也必须是 5 的倍数。后台最多尝试 40 组可复现的随机车库，每组均用正式玩法引擎验证；**只有找到无道具通关路线才替换草稿**，并展示派车步骤。若球数不符、车位不足，或 40 组内尚未找到路线，会提示原因并保留原车库；“尚未找到”不代表球区无解。未保存车库将被覆盖时会先确认。随后再修改球或车，需重新验证通关。

“关卡属性”中可设置球区宽高和道路车位上限 **1–36**；内置关卡默认 60×20、6 个车位。这些值随关卡保存和导出，也用于即时试玩与快速验证。道路车辆卡片突出显示剩余容量和初始容量；待发车辆卡片显示尚未派出时的剩余容量。

点击“快速验证无道具通关”会在浏览器后台用正式玩法引擎尝试多条派车路线，编辑器可继续操作。找到路线时显示实际模拟步数、接球数和每辆车的派出时点；这些步骤可以在试玩中复现。逐色容量不匹配时会给出确定的无道具不可通关原因。若搜索预算内没有找到路线，则显示“尚未证实”，**不把未找到误判成无解**。再次修改草稿会自动取消过期验证结果。

在车库选择车辆后可改颜色、容量，选择目标列和位置再点“移动车辆”，或直接删除。选择列并点“新增车辆”可在该列末尾加车；每列最多 12 辆，容量只能是 1–当前球格总数的整数。关卡名称在属性区修改。

统计区实时显示各色球数、车辆初始总容量和差值。结构错误会明确提示并阻止保存、导出和试玩；数量不匹配只警告，允许保存和试玩。数量匹配**不代表**已证明关卡可通关。

- **即时试玩**：用当前编辑数据的副本开局，不要求保存。返回编辑器后涂画、车辆和名称保持原样。
- **快速验证**：在 Web Worker 中试跑真实无道具逻辑；成功给出可复现路线，数量不匹配给出确定原因，其余耗尽预算的情况明确标为未证实。
- **保存到本机**：按当前关卡 ID 写入浏览器 `localStorage`，刷新后恢复；普通游玩也会读取已保存的版本。未保存修改切关前会提示。
- **导出 JSON**：下载当前单关配置，并把同一内容填入导入文本框。
- **导入 JSON**：可粘贴或选择文件，点击“导入到当前关卡”后才会校验并替换草稿。失败时原草稿保持不变；导入的关卡 ID 会映射为当前所选关卡 ID。
- **恢复本关默认**：确认后删除该关本地存档，恢复内置配置。

JSON 顶层为 `{ "version": 5, "level": { ... } }`。`level` 包含非空 `id`、非空 `name`、整数 `width`、`height`、长度为 `width × height` 的 `balls` 数组（每格可填 `R` 红、`B` 蓝、`Y` 黄、`G` 绿、`O` 橙、`P` 紫或 `null`），以及恰好三列的 `garage`。车辆 `color` 使用同一组颜色码，单关可使用其中 1–6 种。`roadCapacity` 为 1–36 的道路车位上限；缺少该字段时按 6 处理。每列车辆按车头到车尾排列，每辆车含唯一 `id`、`color`、`capacity` 和从 0 连续编号的 `slot`。可导入 version 4 的 60×20 配置；旧 version 4 本地存档会自动读取为 60×20，保存后写入新版存储键。原有四色 version 5 配置继续兼容。version 1–3 JSON 不支持直接导入。

## 简化玩法规则

- 球只在本关 `width × height` 矩形内。初始试玩和每次接球后执行确定性网格落球：先试正下方；被挡住时试右下；右下不通再试左下；三处都不通则停下。斜落要求同侧格和斜下目标都为空，不能穿过邻球或球区边界。允许跨列，不保证保持原列颜色顺序。
- 一轮落球按从下到上、同一行从左到右检查，每球每轮最多移动一格；重复轮次直到没有球能移动。每次移动立即更新占用状态，因此同一配置和操作时点得到相同结果。逻辑落点在接球事件后算到稳定，Canvas 按移动路径播放直落和斜落动画；暂停冻结模拟时间，加速只改变模拟时间的推进速度。
- 固定道路随球区宽度伸缩，共有 `width + 68` 个离散位置。前 `width` 个位置紧贴矩形底边，分别只与正上方一个底排球格上下相邻；其余 68 个位置不能接球。球团其他外轮廓不算道路邻接。
- 每车每模拟步前进一个道路位置。接球事件只读取**该步当时**的底排球，且只接同色、容量未满的球。随后立刻执行落球；同一事件不递归吸走补位球，须等车辆再次合法经过。若多车同一步争球，按出车编号先后处理，结果稳定可复现。
- 道路车位上限由关卡配置，范围 1–36，默认 6。只要道路未满，即使当前路车接不到球也能继续派车。满载车立即离场。暂停停止模拟推进；加速仅改变每秒推进的模拟步数。
- 当还有球、道路达到本关上限、落球动画已结束，且任一路车未来绕行至全部接球路段也接不到当前底排球时，判为死局。未到接球路段但未来可接到球的车不会导致提前判负。
- 运力不足与“道路满位死局”分开提示；编辑器允许不匹配草稿，游戏不会替玩家删球、补车或改变通关条件。

快速验证采用有限数量的启发式派车策略，属于寻找通关路线的辅助工具，不是穷尽式自动求解器，也不提供自动难度评分。内置关卡人工配置；测试脚本回放已记录的出车路线，并用同一玩法引擎回放随机关卡样本。

## 主要文件

当前按四色九关难度节奏制作的六色关卡包位于 [`level-pack-40x40-six-color-matched/`](./level-pack-40x40-six-color-matched/README.md)。每关是可导入的 version 5 JSON，附设计比较、逐车解法和正式引擎回放脚本。更难的六色版留在 `level-pack-40x40-six-color-hard/`；较早六色版和四色参考版分别在 `level-pack-40x40-six-color/`、`level-pack-40x40/`。

- `src/levels.js`：三个内置关卡的人工配置。
- `src/constants.js`：统一定义矩形边界和合法格子。
- `src/generator.js`：按颜色生成矩形关卡草稿，或按列行数为当前球区生成容量为 5 的倍数的车辆。
- `src/verifier.js`、`src/verified-garage.js`、`src/verify-worker.js`：无道具派车策略回放、车辆生成筛选与后台验证。
- `src/engine.js`：共享的派车、道路、接球、补位、道具和胜负逻辑。
- `src/gravity.js`：可复现的直落、斜落和动画路径计算。
- `src/validation.js`、`src/storage.js`：配置检查、JSON 与本地保存。
- `pattern-tool.html`、`src/pattern-tool.js`、`src/pattern-layout.js`：图片／字符图案转换、排布预览与文件格式校验。
- `src/render.js`、`src/main.js`、`index.html`、`styles.css`：Canvas 画面、游戏及编辑器交互。
- `tests/`：规则与回放测试；`scripts/`：本地服务、构建和关卡回放。

运行源码服务后可打开 `/tests/mobile-preview.html`，在 390px 宽的内嵌视口检查手机布局。

**已知限制：**道路和车库采用固定几何与三列布局；落球使用网格规则而非真实刚体碰撞。逻辑落点在事件中算到稳定，视觉动画按该路径回放。快速验证的“未证实”不代表无解。浏览器本地存档只在同一浏览器、同一来源下可恢复。

## 换机后的快捷启动

Windows 可双击 start-demo.cmd，保持服务窗口开启，再访问 http://127.0.0.1:4173/ 。启动器优先使用系统 Node.js，否则尝试当前用户 Codex 内置运行环境；两者都不存在时需安装 Node.js 20+。关闭服务可按 Ctrl+C。浏览器本地草稿不会随项目文件迁移，需导入旧电脑导出的关卡 JSON。
